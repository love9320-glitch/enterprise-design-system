> 이 파일은 저장소가 원본입니다(2026-08-10 노트북 메모리에서 이관 — 집/회사 어느 컴퓨터에서든 공유).
> 내용을 갱신하면 저장소에 커밋할 것. 개인 메모리에는 다시 쌓지 않는다.

Figma 파일 `h9jZFkEHfcHUGok1TZjjlP`의 design-system 자산은 **2026-06-24경 사용자가 (Editor만 빼고) 전부 Code Connect 연결**해 둠 — **개별 컴포넌트뿐 아니라 템플릿(TableTemplate 등 복합 단위)도 연결됨.** 확인된 연결: Button·ButtonGroup·SearchBar·Select·Input·Tag·Checkbox·Table·Pagination·**TableTemplate**·Modal·SegmentControl·Label(2026-06-26 추가). **"아직 미연결"이라 단정 금지 — 확인부터.** 작도 시 규칙 3·4(큰 단위 먼저)대로 **템플릿이 덮으면 템플릿을 Code Connect로 찾아 인스턴스화**, 안 되는 부분만 개별 컴포넌트. (규칙서 C구역 규칙 14)

- **검증 도구**: `get_code_connect_map(nodeId)`는 `{figmaNodeId: {componentName, source}}`를 반환. **주의: 조회한 노드의 서브트리 범위만** 돌려줘서 한 번 호출로는 전체가 안 나온다(이걸 부분 결과로 보고 "미연결"이라 잘못 단정한 적 있음 — 2026-06-26).
- **활용(작도 속도)**: 이 맵을 뒤집으면 **컴포넌트명 → Figma nodeId 역인덱스**가 된다 → 레이어 전체 탐색 없이 `getNodeByIdAsync → createInstance`로 바로 인스턴스화. 거의 전 컴포넌트가 연결돼 있어 사실상 완성된 레지스트리. 전체로 쓰려면 한 번 aggregate해 캐시하는 게 좋다(미정 — 필요 시 메모리에 component→nodeId 레지스트리 저장).
- **MCP 매핑 = Dev Mode "Connected" 표시됨**(SearchBar/SegmentControl 등에서 확인). 별도 CLI `figma connect publish` 불필요. variant뿐 아니라 **컴포넌트 SET 노드도 매핑해야** 읽기/표시가 안정적이었음(Label에서 변별: variant만 매핑 시 `get_code_connect_map`이 `{}`였다가 SET 노드 매핑 후 15개 전부 등록 확인).
